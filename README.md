# Sanskrit Saathi 🪷: web app (React + FastAPI)

Learn Sanskrit from the alphabet to Pāṇini. Learners sign up with **email and password**; their progress is stored per account.

```
frontend/   React 18 + TypeScript + Vite (SPA)         → npm run build → dist/
backend/    FastAPI + SQLAlchemy (SQLite dev / Postgres prod)
  app/      auth, course, quizzes, flashcards, lab, tutor endpoints
  saathi/   the language engine: transliteration, sandhi, morphology, syntax, 28 lessons, quiz generators, Gemini layer
```
In production one container serves the API and the built SPA from the same origin (no CORS, cookie-based sessions).

## Language engine (what changed in this version)
* **Wide verb coverage:** 2,229 Dhātupāṭha roots in all ten gaṇas, with parasmaipada, ātmanepada, passive and causative forms; present,
  imperfect, imperative, optative, future, conditional, perfect, aorist and periphrastic future; participles (kta, ktavatu, śatṛ, śānac),
  gerundives (tavya, anīya, -ya), gerunds (ktvā, lyap) and infinitives; prefixed verbs (stacked upasargas, ṣatva, ṇatva).
  Thematic paradigms are generated by explicit rules; athematic, perfect and aorist paradigms are listed (generated offline from the
  Dhātupāṭha, see `NOTICE.md`).
* **Evaluation harness** (`backend/saathi/evaluation`, docs in `backend/docs/EVALUATION.md`): measures coverage and accuracy on the UD
  Sanskrit treebanks, sandhi rule recall, and agreement of generated verb forms with an independent Pāṇinian engine. On classical text:
  finite-verb coverage 32.8% → 98.9%, overall token coverage 38.9% → 58.0%, oracle agreement 99.96% on 387,621 verb cells.
* **Lab → Verbs:** browse any root's paradigms by voice and tense.
* Memory/start-up: the verb index is built in a background thread at start (about 2 s, roughly 210 MB RAM in total). Set `WARM_ENGINE=0` to skip.

## Features
Home dashboard (XP, level, streak, badges, roadmap) · **28 lessons in 4 levels** with graded quizzes (70% completes a lesson) · Devanagari script trainer · daily challenge, mixed review, placement test · spaced-repetition flashcards · Gemini tutor (general or lesson-aware, with verified grammar tools) · linguistics lab (sentence analysis, sandhi join/split, paradigms, transliteration, self-check) · account settings (change password, export/import progress, delete account).

Quiz answers for declension, conjugation, case spotting and sandhi are generated and **graded on the server** by the rule engine; the correct answer is never sent to the browser before you answer.

## Run in development (two terminals)
```bash
# 1. API  (http://localhost:8000, docs at /docs)
cd backend
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
export GEMINI_API_KEY=your-key                         # optional; without it the tutor runs in offline demo mode
uvicorn app.main:app --reload --port 8000

# 2. Web app (http://localhost:5173, proxies /api to the API)
cd frontend
npm install
npm run dev
```
Password-reset emails are printed to the API log when SMTP isn't configured.

## Deploy
```bash
cp .env.example .env        # set SECRET_KEY, POSTGRES_PASSWORD, APP_BASE_URL, GEMINI_API_KEY ...
docker compose up --build   # http://localhost:8000
```
Put it behind HTTPS (Caddy, nginx, Fly.io, Render, Railway...). Session cookies are `Secure` in production, so plain-http testing needs `COOKIE_SECURE=false`.
Hosting without Docker: `npm run build` in `frontend/`, then run `uvicorn app.main:app` from `backend/` with `FRONTEND_DIST=../frontend/dist`.

## Configuration (environment)
| Variable | Purpose |
|---|---|
| `SECRET_KEY` | **Required in production.** Signs session tokens |
| `DATABASE_URL` | `sqlite:///./saathi.db` (default) or `postgresql://user:pass@host/db` |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | AI tutor (key stays on the server). Default model `gemini-3.8-flash` |
| `AI_DAILY_LIMIT` | AI requests per user per day (default 60) |
| `APP_BASE_URL`, `CORS_ORIGINS` | Public URL (reset links) and allowed browser origins |
| `SMTP_*` | Password-reset email |
| `COOKIE_SECURE`, `SESSION_DAYS` | Cookie flag (default on in production) and session length (14 days) |

## Security design
- Passwords hashed with **scrypt** (salted); login responses are identical for unknown email and wrong password, with equalised timing.
- Session = signed JWT in an **httpOnly, SameSite=Lax** cookie (not readable by JavaScript). State-changing requests must carry `X-Requested-With: saathi`, which cross-site pages cannot add, so CSRF is blocked.
- Rate limits: 8 login attempts / 15 min per IP+email, 10 sign-ups / hour and 5 reset requests / hour per IP. Reset tokens are random, stored hashed, single-use, valid 1 hour.
- Security headers incl. a strict CSP; user data is rendered as text (no raw HTML); all inputs validated by Pydantic.
- Quizzes are graded server-side and scoped to their owner.

## Known limits (read before launching publicly)
- **No email verification** yet (anyone can register any address) and no "log out everywhere".
- Rate limiting is in memory, so run one worker or move it to Redis. Tables are created on start; add Alembic migrations before changing the schema in production.
- Progress is one JSON document per user: simple and fast, but last-write-wins if the same account is used in two tabs at once.
- Streak and daily goal use the **server's** date, not the learner's time zone.
- Language engine limits: prefix-conditioned ātmanepada (saṃgacchate, adhīte), Vedic moods, consonant-stem nouns, compounds and splitting of out-of-lexicon words are not covered; rare roots' forms come from a derivation engine and were not reviewed by hand. See `backend/docs/EVALUATION.md`.
- The lesson text was written for this app and cross-checked against the rule engine where it can generate forms; have a Sanskrit teacher review Levels 3–4 prose before classroom use. The engine's lexicon is small, so "not found" means *not covered*.
- AI replies can be wrong; the app flags what the rule engine can verify. A shared Gemini key bills you for all learners, so keep `AI_DAILY_LIMIT` modest.
